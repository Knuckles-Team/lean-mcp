# CONN-LEAN-MCP — Requirements

| ID | Requirement | Acceptance |
|---|---|---|
| `CONN-LEAN-MCP-R001` | **Check.** The tool `lean_check` checks a project, a file or one declaration against the pinned toolchain. It returns the receipt fields `checker_id`, `toolchain_version`, `declaration`, `artifact_digest`, `axioms`, `has_sorry` and `verdict`. The receipt fails on `sorry`. It lists every axiom that `#print axioms` reports, including nonstandard ones. A toolchain other than the pin is refused with `TOOLCHAIN_MISMATCH`. A run past `LEAN_TIMEOUT_S` is killed and refused with `CHECK_TIMEOUT`. Every `lean` and `lake` call runs as a subprocess in `lean_mcp/runner.py`, inside `LEAN_WORKSPACE_ROOT`. Code path: `lean_mcp/api_client.py::Api.check` → `LeanRunner.run`. Caller chain: MCP tool `lean_check` → `lean_mcp/api_client.py::Api.check` → `LeanRunner.toolchain_version` and `LeanRunner.run` → `lean_mcp/receipt.py::build_receipt`. Shape: `lean_mcp/api_client.py`, `lean_mcp/runner.py` and `lean_mcp/receipt.py`; reuse `LeanRunner.run` for every process. | Test: `tests/test_check.py::test_a_clean_proof_passes_with_standard_axioms`, `tests/test_check.py::test_sorry_fails_the_receipt`, `tests/test_check.py::test_nonstandard_axioms_are_reported`, `tests/test_check.py::test_toolchain_mismatch_is_refused`, `tests/test_runner.py::test_a_timeout_kills_the_process_and_refuses`. |
| `CONN-LEAN-MCP-R002` | **Extract.** The tool `lean_extract` lists the declarations of a project with their kind (`theorem`, `definition`, `structure`, `inductive`, `instance`) and module. It lists dependency edges between declarations and import edges between modules. Lean's own environment supplies them: `lean_mcp/lean/Extract.lean` runs inside `lake env lean --run`. Code path: `lean_mcp/api_client.py::Api.extract` → `Api._extract` → `LeanRunner.run`. Caller chain: MCP tool `lean_extract` → `Api.extract` → `Api._extract` → `LeanRunner.run`. Shape: `lean_mcp/api_client.py` and `lean_mcp/lean/Extract.lean`; reuse `LeanRunner.run`. | Test: `tests/test_extract.py::test_extract_returns_declarations_and_edges`, `tests/test_extract.py::test_a_failed_build_is_refused`. |
| `CONN-LEAN-MCP-R003` | **Pack.** The ontology pack `lean_mcp/ontology/lean.ttl` declares `lean:Declaration`, its subclasses `lean:Theorem`, `lean:Definition`, `lean:Structure` and `lean:Instance`, `lean:LeanModule`, `lean:leanDependsOn` and `lean:declaredIn`. Every class extends a core class and every property extends a core property. The pack redeclares no core term and never imports core. The core classes `Module` and `dependsOn` already exist, so the pack names its own terms `LeanModule` and `leanDependsOn`. The one-schema shadow check reports zero violations. Caller chain: the SDK serves `lean_mcp/ontology/lean.ttl` as the `ontology://` resource at server start. Shape: `lean_mcp/ontology/lean.ttl` only; reuse the core terms `Concept`, `Module`, `dependsOn` and `partOf`. | Test: `tests/test_pack.py::test_pack_extends_core_and_redeclares_nothing`. |
| `CONN-LEAN-MCP-R004` | **Surfaces.** Each tool carries a skill, a prompt and a tool-use contract. `lean_check` has the skill `lean-proof-checking`. `lean_extract` has the skill `lean-declaration-extraction`. Both appear in the prompts `lean-operator` and `lean-verifier` and in one contract each. The `connector-standard` gate passes with no `SKIP`. Caller chain: the SDK reads `lean_mcp/connector_contracts.py` and serves the prompts and skills of `lean_mcp/` at server start. Shape: `lean_mcp/connector_contracts.py`, `lean_mcp/prompts/` and `lean_mcp/skills/`; reuse the SDK `ToolUseContract` and `SurfaceLink` types. | Test: `tests/test_surface.py::test_every_tool_has_a_contract_a_prompt_and_a_skill`. |
